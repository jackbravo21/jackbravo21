Diretorios:


Eh a configuracao que sobe para o servidor.


/config/app.php

Nome da aplicacao:
	'name' => env('APP_NAME', 'Laravel'),



Vai verificar se existe algum valor na ".env" na linha "APP_ENV=local", se nao tiver, ele assume a config do "production". Quando vc sobe para o servidor, ele nao vai encontrar a linha do "APP_ENV" dentro do ".env", vai assumor o "production".
	'env' => env('APP_ENV', 'production'),



Vai ficar como False, quando nao tiver nada no debug, ja vai estar valendo, em producao. Ele procura na linha "APP_DEBUG=true" do ".env", como nao vai estar o ".env" em producao, nao vai achar, e vai ser "false".
	'debug' => (bool) env('APP_DEBUG', false),



URL voce pode trocar quando tiver um dominio:
	'url' => env('APP_URL', 'http://localhost'),
	'asset_url' => env('ASSET_URL', null),



A chave por default ela pega apenas no ".env" o "APP_KEY=base64:QgpvyWNRDUzFkglcHCroAvuUqbImUSD8Sco8cj29oxA=". 
	'key' => env('APP_KEY'),
	'cipher' => 'AES-256-CBC',

Quando subir para o servidor, se nao tiver a chave, nao vai funcionar, como nao vai o ".env", deve-se colocar a chave no lugar. Assim:
	'key' => env('base64:QgpvyWNRDUzFkglcHCroAvuUqbImUSD8Sco8cj29oxA='),
	'cipher' => 'AES-256-CBC',

Para criar rota:
- Route.
- Metodo: get
- Caminho '/caminho'
- Rota, que vai encaminhar para um controller, ou uma funcao ('/', AQUI());

----------------------------------------------------------------------
	Route::get('/contato', function(){
    	return "Contato";
	});
----------------------------------------------------------------------

Rota para receber um ID:
----------------------------------------------------------------------
	Route::get('/contato/{id}', function($id){
   	return "Contato id = $id";
	});
----------------------------------------------------------------------
Vou receber um (id), e na funcao ela vira uma variavel, que recebe.


Valor padrao, nao obrigatorio:
----------------------------------------------------------------------
	Route::get('/contato/{id?}', function($id=null){
    	return "Contato id = $id";
	});
----------------------------------------------------------------------

Vou criar agora um contato vazio, e usar um formulario.
----------------------------------------------------------------------
	Route::post('/contato', function(){
  	  return "Contato POST";
	});

----------------------------------------------------------------------

Crio la dentro da view na "welcome.blade.php" e usar o "{{ csrf_field() }}" ou "@csrf" para usar o token, gerando dentro do form, no form action eu uso a rota definida no web.php como "/contato":
----------------------------------------------------------------------
                <div>
                    <h2>Teste com Rotas:</h2>
                    <form action="/contato" method="post">
			{{ csrf_field() }}

Verificar dados dentro do POST do contato:

	Route::post('/contato', function(){
 	   var_dump($_POST);

Mas o laravel possui um metodo chamado DD. Eh um varDump diferente, que da um exit, parando a aplicacao.

	});

Controller:

Para criar o Controller, eles ficam no "/app/Http/Controllers/".

O "/app/Http/Controllers/Controller.php" eh o principal, e serve como modelo para os controllers proprios.


- php artisan make:controller NOME_DO_CONTROLLER

- php artisan make:controller ContatoController

Nele, podemos colocar os metodos.


Para configurar a rota, para que a rota entregue o controller, ao inves de funcao, envio um array, passando uma chave, e o valor desta chave vai ser o valor do controller, e especifico o metodo dentro do controller com @, no caso metodo index:
----------------------------------------------------------------------
	Route::get('/contato/{id?}', ['uses'=>'ContatoController@index']);
----------------------------------------------------------------------

Dentro do ContatoController.php configuramos o metodo, metodo index:
----------------------------------------------------------------------
class ContatoController extends Controller
{
    public function index(){
        return "Esse eh o Index do ContatoController";
    }
}
----------------------------------------------------------------------

Agora eu configuro o POST e o PUT com as rotas, soh mudando o metodo, para criar e editar:
----------------------------------------------------------------------
Route::get('/contato/{id?}', ['uses'=>'ContatoController@index']);

Route::post('/contato', ['uses'=>'ContatoController@criar']);

Route::put('/contato', ['uses'=>'ContatoController@editar']);

Para pegar as informacoes no controller, ele tem os "requests", etc. E declaro uma variavel para ele (pode ser qualquer nome). Tenho que chamar adicionar a biblioteca requests com use. E depois posso usar um dd, chamando a variavel com o campo nome.

Views:

Retornando Views, ao inves de texto, devo utilizar o metodo view(), ao qual ele recebe alguns parametros, o primeiro eh dizer onde esta a view, eu posso dizer tambem se ela esta dentro de algum diretorio, o primeiro diretorio que ela vai olhar eh o "/resources/views/";
Esta view estara dentro da pasta "/contato/" e tera o nome "index", entao ficara "/resources/views/contato/index.blade.php", e na funcao, eu vou retornar a views com o caminho, soh que ao inves de "/" eu uso ".", como abaixo.

"('contato.index',compact('contatos'))", 

Se eu tivesse mais de uma lista, soh precisaria colocar uma ",":
"('contato.index',compact('contatos','outralista'))", 

ou utilizar um array "('contato.index', ["dados"=>])";

##############################################################		Migracoes


Migracoes sao um controle de versao sobre tudo que for fazer no banco de dados, vamos modelar o banco com o PHP.
Podemos dar rollback no banco, voltando as migracoes tambem.

"/database/migrations/"


Pode verificar as sintaxes no endereco, na parte "Available Column Types":
"https://laravel.com/docs/7.x/migrations"


Criando nova migracao:

#> php artisan make:migration NomeDaMigracao

Para preparar automatico e ele criar com todos os componentes e montar a estrutura de "produtos" por exemplo:

#> php artisan make:migration create_produtos_table --create=produtos

Resultado:
Created Migration: 2020_05_12_031520_create_produtos_table

Arquivo criado: "/database/migrations/2020_05_12_031520_create_produtos_table";

<?php

use Illuminate\Database\Migrations\Migration;

----------------------------------------------------------------------
    public function salvar(Request $req){
        
        $dados = $req->all();
        
        //teste para ver se foi clicado em publicado. Campo obrigatorio.
        if(isset($dados['publicado'])){
            $dados['publicado'] = 'sim';
        }else{
            $dados['publicado'] = 'nao';
        }
                
        //vou tratar a imagem e adicionar no banco, para tratar vou pegar a $req e vou usar um metodo que verifica se existe arquivos "hasFile", que vai verificar se existe alguma imagem.
        if ($req->hasFile('imagem')){
            $imagem = $req->file('imagem');
            //vou criar uma variavel para colocar um numero randomico para ser colocado o nome da imagem, com rand;
            $num = rand(1111,9999);
            //Diretorio que eu vou salvar a imagem:
            $dir = "img/cursos/";
            //defino a extensao do arquivo com um metodo do Laravel guessClientExtension();
            $ex = $imagem->guessClientExtension();
            //crio o nome do arquivo juntando os recursos.
            $nomeImagem = "imagem_".$num.".".$ex;
            //agora vou usar o metodo "move" que vai mover a imagem para o diretorio, parametro: "diretorio, nome_da_imagem);
            $imagem->move($dir,$nomeImagem);
            //preciso atribui o nome e o caminho desta imagem para salvar no banco. Pegando das variaveis.

class LoginController extends Controller

    public function index(){
        return view('login.index');
    }
    //metodo para entrar, onde redireciona para o login com mensagem de erro, caso nao de certo, vamos validar com uma Requesicao, e validar com um metodo attemp.
    public function entrar(Request $req){
        //vamos verificar no banco, o email que esta pegando pelo $dados, que esta chamando all (todos os atributos);
        $dados = $req->all();
        if(Auth::attempt(['email'=>$dados['email'], 'password'=>$dados['senha']])){
           return redirect()->route('admin.cursos');
        }
        return redirect()->route('login.index');
    }
    public function sair(){
        //executa o metodo Auth, e ele possui outro metodo logout, executa o metodo e redireciona.

        return redirect()->route('site.home');
    }
}
