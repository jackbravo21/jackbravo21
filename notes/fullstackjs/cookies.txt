Cookies são pequenos pedaços de dados que o servidor envia ao cliente (navegador), que os armazena e envia de volta ao servidor em cada requisição subsequente. Eles podem ser usados para armazenar informações de sessão, como o token de autenticação.

Básico sobre Cookies:
Armazenamento de Cookies: Quando o navegador recebe um cookie, ele o armazena localmente, geralmente até que ele expire, e o envia automaticamente para o servidor em requisições subsequentes.

Formato do Cookie:

Nome: Identifica o cookie.
Valor: Contém a informação (no seu caso, pode ser o token).
Data de Expiração (opcional): Indica quando o cookie deve expirar.
Caminho (opcional): Define a URL ou diretório em que o cookie é válido.
Secure (opcional): Se estiver presente, o cookie só será enviado em requisições HTTPS.
HttpOnly (opcional): Se definido, o cookie não pode ser acessado via JavaScript (só via HTTP, ou seja, não exposto ao front-end).
Exemplo básico de uso no Front-End com JavaScript:
Definindo um Cookie
javascript
Copiar código
document.cookie = "token=seu_token_aqui; path=/; expires=Sat, 1 Jan 2025 12:00:00 UTC; secure; HttpOnly";
token é o nome do cookie.
seu_token_aqui é o valor do cookie (o token que você quer armazenar).
path=/ define o caminho onde o cookie é válido (o cookie será enviado para todas as páginas do seu site).
expires=Sat, 1 Jan 2025 12:00:00 UTC define a data de expiração.
secure faz com que o cookie seja enviado apenas em conexões seguras (HTTPS).
HttpOnly impede que o cookie seja acessado pelo JavaScript (só o servidor pode acessá-lo).
Acessando o Cookie
javascript
Copiar código
const getCookie = (name) => {
    const value = `; ${document.cookie}`;
    const parts = value.split(`; ${name}=`);
    if (parts.length === 2) return parts.pop().split(';').shift();
};

const token = getCookie('token');
console.log(token);  // Exibe o token armazenado no cookie
Removendo um Cookie
Para remover um cookie, basta definir sua data de expiração para uma data no passado:

javascript
Copiar código
document.cookie = "token=; path=/; expires=Thu, 01 Jan 1970 00:00:00 UTC; secure; HttpOnly";
Vantagens dos Cookies:
Persistência: Cookies são enviados automaticamente em todas as requisições subsequentes, então você não precisa se preocupar em enviar o token manualmente em cada requisição.
Segurança: Com a flag HttpOnly, o cookie fica inacessível ao JavaScript, o que o torna mais seguro contra ataques como XSS (Cross-Site Scripting).
Controle de Expiração: Você pode definir a expiração do cookie conforme necessário, o que é útil para sessões de login.
Desvantagens:
Limitação de Tamanho: O tamanho máximo de um cookie é limitado (geralmente até 4 KB).
Vulnerabilidade a CSRF (Cross-Site Request Forgery): Cookies são enviados automaticamente pelo navegador em todas as requisições, o que pode ser um risco se não forem usados com segurança adequada.
Agora que você tem o básico, se quiser implementar isso no seu projeto, posso te ajudar a configurar o armazenamento e o envio de cookies para autenticação.

Nesse caso:

Como o token está no cliente (e visível), ele é mais vulnerável a ataques, como XSS (Cross-Site Scripting).

Exemplo de Configuração:
javascript
Copiar código
res.cookie('token', token, {

Nesse caso:

O navegador automaticamente envia o cookie em cada requisição para o backend, tornando a experiência mais segura e transparente.

Comparação Direta:
Método	Visível para o Frontend?	Transmissão	Armazenamento	Segurança
Bearer Token	Sim	Cabeçalho HTTP (Authorization)	localStorage ou sessionStorage	Vulnerável a XSS (se exposto ao JavaScript).

Bearer Token: Útil quando você precisa de mais controle no frontend (por exemplo, múltiplos tokens para diferentes serviços ou APIs).
Cookies: Ideal para sistemas que priorizam segurança e desejam simplificar a autenticação, especialmente em SPAs ou aplicações full-stack.
Se seu objetivo é segurança e menor risco de exposição, os cookies são a melhor escolha.

Sim, é possível criar dois cookies no backend com diferentes configurações, incluindo um httpOnly para maior segurança e outro com httpOnly: false que pode ser acessado pelo frontend. Essa abordagem pode ser útil em cenários onde você precisa balancear segurança e funcionalidade.

Aqui está como você pode fazer isso:

Exemplo de Código para Criar Dois Cookies:
javascript
Copiar código
const jwt = require('jsonwebtoken');

const checkLogin = async (req, res) => {
    const user = { id: 1, email: 'user@example.com' }; // Exemplo de dados do usuário

    const token = jwt.sign(
        { userId: user.id, email: user.email }, // Payload
        process.env.JWT_SECRET,               // Chave secreta
        { expiresIn: '3h' }                   // Tempo de expiração
    );

    // Cookie seguro, inacessível pelo frontend
    res.cookie('token', token, {
        httpOnly: true,
        secure: true,
        sameSite: 'strict',
        maxAge: 3 * 60 * 60 * 1000 // 3 horas
    });

    // Cookie acessível pelo frontend
    res.cookie('token_accessible', token, {
        httpOnly: false, // Permite acesso via JavaScript
        secure: true,
        sameSite: 'strict',
        maxAge: 3 * 60 * 60 * 1000 // 3 horas
    });

    res.status(200).json({ message: "Login realizado com sucesso!" });
};
Motivações para Criar Dois Cookies:
Segurança com httpOnly:

O cookie httpOnly armazena o token de autenticação de maneira segura, impedindo acesso via JavaScript (proteção contra XSS).
Este cookie é usado pelo backend para validar o usuário automaticamente.
Acessibilidade no Frontend:

O cookie sem httpOnly permite que o frontend acesse o token, caso seja necessário para funcionalidades específicas, como exibição de dados ou envio em headers personalizados.
No entanto, isso também expõe o token a ataques XSS.
Considerações Importantes:
Evite Redundância: Se você não tem um motivo claro para expor o token no frontend, prefira usar apenas o cookie httpOnly.
Use Tokens Diferentes, se Necessário: Você pode gerar um segundo token com informações limitadas, caso precise expô-lo ao frontend, reduzindo o risco de vazamento de informações sensíveis.
Risco de XSS: O cookie acessível pelo frontend está vulnerável a ataques XSS. Certifique-se de implementar medidas de segurança como:
Sanitização de entradas de usuário.
Uso de Content Security Policy (CSP).
Evite Dupla Autenticação: Não confunda a lógica do backend ao tentar usar ambos os cookies para validar uma requisição. Sempre priorize o httpOnly para autenticação.
Melhor Abordagem:
Ideal: Utilize apenas o cookie httpOnly para autenticação.
Exceção: Só adicione o cookie acessível pelo frontend (httpOnly: false) se tiver um motivo funcional claro. Por exemplo, se você precisa de uma parte do token para exibir informações específicas no frontend, mas sem comprometer a segurança geral.

Sim, você está certo em pensar que, por padrão, os cookies podem ser vulneráveis, especialmente quando armazenam dados sensíveis. No entanto, você pode criptografar os dados armazenados nos cookies para aumentar a segurança e dificultar o acesso ou a modificação por parte de um atacante.

Como funciona a criptografia de cookies?
Ao criptografar os dados antes de armazená-los em um cookie, você está garantindo que, mesmo que alguém consiga acessar o conteúdo do cookie, eles não possam ler ou modificar esses dados sem a chave secreta de criptografia.

Aqui está um exemplo básico de como você pode fazer isso no backend usando Node.js:

1. Criptografando e Descriptografando os Dados no Backend
Você pode usar uma biblioteca como crypto (integrada no Node.js) ou bibliotecas externas como jsonwebtoken ou crypto-js para criptografar os dados.

Exemplo de Criptografia com crypto:
Criptografando os dados (antes de colocar no cookie):

javascript
Copiar código
const crypto = require('crypto');

// Função para criptografar
function encryptData(data) {
    const cipher = crypto.createCipheriv('aes-256-cbc', process.env.CRYPTO_KEY, process.env.CRYPTO_IV);
    let encrypted = cipher.update(data, 'utf8', 'hex');
    encrypted += cipher.final('hex');
    return encrypted;
}

// Criptografando os dados do usuário
const encryptedUserData = encryptData(JSON.stringify({
    id: user.id,
    mail: user.mail,
    fullname: user.fullname,
    administrator: user.administrator,
    createdAt: user.created_at,
}));

res.cookie('userData', encryptedUserData, {
    httpOnly: true,
    secure: true,
    sameSite: 'strict',
    maxAge: 3 * 60 * 60 * 1000, // 3 horas
});
Descriptografando os dados (quando for preciso acessar no backend):

javascript
Copiar código
// Função para descriptografar
function decryptData(encryptedData) {
    const decipher = crypto.createDecipheriv('aes-256-cbc', process.env.CRYPTO_KEY, process.env.CRYPTO_IV);
    let decrypted = decipher.update(encryptedData, 'hex', 'utf8');
    decrypted += decipher.final('utf8');
    return decrypted;
}

// Descriptografando os dados ao obter do cookie
const encryptedUserData = req.cookies.userData;
if (encryptedUserData) {
    const userData = decryptData(encryptedUserData);
    const user = JSON.parse(userData);
    console.log(user); // Agora você tem os dados do usuário decodificados
}
2. Criptografia com JSON Web Token (JWT)
Outra abordagem segura e moderna é usar o JWT para armazenar as informações de forma compacta e segura. O JWT já inclui assinatura, o que garante a integridade dos dados, e você pode adicionar criptografia se precisar de um nível extra de segurança.

Ao usar JWT, você pode enviar informações diretamente no cookie sem se preocupar com a manipulação dos dados.

JWT com assinatura: Garante que o token não seja alterado.
JWT com criptografia (opcional): Garante que o conteúdo do token seja invisível para qualquer pessoa que tenha acesso ao cookie.
Exemplo de uso com JWT:
Gerando o JWT (com dados criptografados):

javascript
Copiar código
const jwt = require('jsonwebtoken');

const payload = {
    id: user.id,
    mail: user.mail,
    fullname: user.fullname,
    administrator: user.administrator,
    createdAt: user.created_at,
};

const token = jwt.sign(payload, process.env.JWT_SECRET, { expiresIn: '3h' });

res.cookie('userDataToken', token, {
    httpOnly: true,
    secure: true,
    sameSite: 'strict',
    maxAge: 3 * 60 * 60 * 1000, // 3 horas
});
Verificando o JWT (descriptografando no backend):

javascript
Copiar código
const jwt = require('jsonwebtoken');

const token = req.cookies.userDataToken;
if (!token) {
    return res.status(403).json({ message: "Token não fornecido!" });
}

try {
    const decoded = jwt.verify(token, process.env.JWT_SECRET);
    req.user = decoded;
    next();
} catch (error) {
    return res.status(403).json({ message: "Token inválido!" });
}
3. Quando usar criptografia no cookie?
Quando armazenar dados sensíveis (ex: informações pessoais, permissões, etc.) e você quer garantir que eles não possam ser lidos ou manipulados facilmente, mesmo que alguém consiga acessar os cookies no frontend.

Quando for importante garantir a integridade e confidencialidade dos dados durante a transmissão entre o servidor e o cliente (ex: dados de login, preferências do usuário, etc.).

Resumo:
Criptografar os dados antes de armazená-los em cookies aumenta a segurança e dificulta que um atacante consiga acessar ou modificar esses dados.
JWT pode ser uma alternativa mais simples para garantir a integridade e segurança dos dados, já que ele já oferece a assinatura e a verificação da autenticidade.
Lembre-se de que a criptografia adiciona complexidade, mas pode ser uma boa prática para proteger dados sensíveis.
